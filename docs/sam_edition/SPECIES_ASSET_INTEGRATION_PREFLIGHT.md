# Sam Edition species asset-integration preflight

This checklist records the proven fixes from the Miltank, Magneton, and Leafeon packets and is the required preflight for remaining Pokémon-specific asset work.

## Scope

Apply this before opening focused QA for every unfinished Pokémon asset packet, including remaining species-specific overworld sprites and custom-species battle/UI graphics.

Do not reopen already-completed species merely to conform them to this checklist unless live QA reveals a regression.

## Overworld/static Pokémon assets

For a dedicated 16x16 nine-frame object-event sprite:

- graphics payload is indexed 4bpp;
- frame size is 128 bytes;
- nine logical frames are present, for a total 1152-byte graphics payload;
- east-facing frames may be generated by horizontal mirroring from west-facing frames;
- palette index 0 is transparency;
- maximum 16 palette entries;
- no alpha, anti-aliasing, or gradients;
- the allocated OBJ_EVENT_GFX id remains below OBJ_EVENT_GFX_VARS and NUM_OBJ_EVENT_GFX is advanced correctly;
- graphics-info pointer registration is present;
- palette routing is explicit and compile-safe.

### Magneton compile-failure prevention

Any standalone object-graphics translation unit that uses `OBJ_EVENT_PAL_TAG_NONE` must provide or include a valid definition in that translation unit. Do not assume another source file's private macro is visible.

The proven safe local value in the current Sam object-event packets is:

`#define OBJ_EVENT_PAL_TAG_NONE 0x11FF`

Likewise, any reused palette tag must be explicitly available to the translation unit, either through an authoritative shared declaration or a deliberate local constant matching the registered palette tag.

## Custom battle/UI species assets

Before registration, verify source PNGs are valid native indexed assets and their PNG chunk CRCs are valid. Re-encode losslessly when necessary rather than accepting malformed indexed PNG containers.

For each custom species packet verify all required registrations together:

- front battle sprite;
- back battle sprite;
- normal palette;
- shiny palette;
- front/back coordinate metadata;
- party/menu icon and icon palette index;
- Pokédex footprint;
- graphics declarations and species-indexed table entries;
- existing cry routing remains unchanged unless the species authority explicitly changes it.

The generated engine resources must be the expected native GBA forms used by the existing build pipeline (for example `.4bpp.lz`, `.gbapal.lz`, icon `.4bpp`, and footprint `.1bpp`).

## CI interpretation

A modified Sam Edition ROM is not expected to match the stock FireRed SHA-1.

Acceptance requires distinguishing:

1. compile/link/ROM-generation failures — real failures that must be fixed;
2. focused contract/runtime failures — real failures that must be fixed;
3. the stock `Compare FireRed` checksum mismatch after a successful modified-ROM build — expected and not a Sam Edition source failure.

Never report PASS unless the modified ROM actually compiles/links/generates successfully and the packet's focused verification passes.

## Static-encounter runtime contract

Where the species packet includes a one-time static encounter, verify the authoritative encounter behavior rather than inferring it from another species. At minimum verify:

- exact map/object placement and facing;
- exact level, held item, and any explicitly locked moves/IV package;
- completion flag allocation;
- capture/defeat/flee branching;
- object removal behavior;
- any defeat reward or bag-space guard required by the encounter authority;
- completion state persists through save/reload;
- flee/non-completion does not permanently remove the encounter.

## Current forward application

- Onix already follows the compile-safe local `OBJ_EVENT_PAL_TAG_NONE` pattern on the current production packet.
- Future Lickitung overworld work must use this preflight before QA.
- Future Ectoceon and other custom-species battle/UI asset packets must use the Leafeon native-indexed/CRC validation pattern before QA.
- Glaceon or any subsequently authorized appended species must use the same asset and CI gates once its current species architecture/authority is established.
